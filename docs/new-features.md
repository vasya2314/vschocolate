# Новые возможности: календарь, карточка клиента, быстрая смена статуса, отчёты в Telegram

Ветка: `feature/calendar-client-card-tg-reports`

## 1. Календарь заказов

**Где:** пункт «Календарь» в меню, кнопка «Календарь» в списке заказов, адрес `/orders/calendar`.

- Два режима: **Месяц** и **Неделя** (`?view=month|week`), стрелки «назад/вперёд», кнопка «Сегодня».
  Конкретный период открывается через `?date=Y-m-d`.
- Каждый заказ в ячейке дня: точка цвета статуса, время выдачи, **№ заказа** и товары.
  При наведении видны клиент, сумма и статус. Клик открывает страницу заказа.
- В режиме «Неделя» под заказом ещё клиент, сумма и долг, если заказ оплачен не полностью.
- Отменённые заказы зачёркнуты и не входят в сумму дня.
- Клик по числу дня открывает список заказов за этот день.
- На телефоне вместо сетки показывается список по дням (только дни с заказами и сегодня).

Файлы: `OrderController::calendar`, `resources/views/pages/orders/calendar.blade.php`.

## 2. Переход от графика на главной к заказам дня

- Клик по столбцу графика «Заказы по дням» открывает список заказов за этот день.
- На телефоне первый тап показывает подсказку, второй открывает заказы.
- В фильтр заказов добавлены поля **«Дата выдачи с / по»** (`date_from`, `date_to`), ими можно пользоваться и вручную.

Файлы: `OrdersChartBlockComposers`, `components/blocks/orders-chart.blade.php`, `OrderFilter`, `Order/IndexRequest`.

## 3. Смена статуса без перезагрузки страницы

- В списке заказов и в карточке клиента бейдж статуса стал выпадающим списком.
- Новый статус сохраняется асинхронно, без перезагрузки: `PATCH /orders/{order}/status` через axios, ответ в JSON.
  Пока идёт сохранение, показывается индикатор загрузки, после него зелёная галочка.
  При ошибке значение откатывается, а у значка ошибки появляется подсказка с её текстом.
- Без JavaScript форма отправляется обычным способом с редиректом назад.
- Имя клиента в списке заказов стало ссылкой на его карточку.

Файлы: `components/orders/status.blade.php`, `OrderController::updateStatus`, `Order/UpdateStatusRequest`.

## 4. Карточка клиента

**Где:** страница клиента `/clients/{id}`, раньше на её месте была только форма редактирования.

- Шапка: имя, телефон (по нажатию звонит), площадка, дата первого и последнего заказа.
- Плашки: **число заказов** (и сколько отменено), **общая сумма**, **средний чек**, **долг**.
  Отменённые заказы в суммы не входят.

- В самом низу **история заказов** по 20 на странице, с быстрой сменой статуса.

## 5. Telegram

### Расписание

| Команда | Когда | Что присылает |
|---|---|---|
| `app:tg-orders-notification` | ежедневно в 8:00 | Заказы к выдаче на 3 дня + кнопки **«✅ Выполнен»** и **«📦 Выдан»** |
| `app:tg-daily-summary` | ежедневно в 20:00 | Итог дня: выдано и на какую сумму, недоплата, что не выдано, новые заказы и клиенты, план на завтра |
| `app:tg-weekly-report` | воскресенье в 20:30 | Неделя: выручка и выдано (с изменением к прошлой неделе), средний чек, новые заказы и клиенты, отмены, топ-3 товара, долг клиентов, план на следующую неделю |
| `app:tg-unpaid-reminder` | пн и чт в 11:00 | Выданные, но не полностью оплаченные заказы: клиент, телефон, долг. Если должников нет, ничего не отправляет |

У команд итога дня и отчёта за неделю есть параметр `--date=Y-m-d`, чтобы вручную отправить их за прошлый период.

### Кнопки в утреннем сообщении

- Кнопки есть только у заказов, которые ещё не выданы и не отменены.
- После нажатия сообщение обновляется само: меняются статусы, лишние кнопки пропадают.
- Кнопки работают только в чате, указанном в настройках.
- Кнопка не переводит статус назад: выданный заказ не станет снова «Выполнен», отменённый не меняется.
- Нажатия приходят на webhook `POST /tg/webhook`. Он исключён из проверки CSRF и защищён секретом
  в заголовке `X-Telegram-Bot-Api-Secret-Token` и ограничением 60 запросов в минуту.

Файлы: `app/Services/TgBot.php` (общий клиент Bot API), `TgWebhookController`,
`Actions/TgNotification/Prepare*Action.php`, `Console/Commands/Tg*.php`, `routes/console.php`, `routes/web/TgRoutes.php`.

### Что ещё поменялось
- Названия товаров в сообщениях экранируются. Раньше символ `<` или `&` в названии мог сломать сообщение.
- Ошибки Telegram, как и раньше, пишутся в `storage/logs/tg-notify.log`.

## Что сделать после деплоя

1. **Подключить кнопки бота:** «Настройки» → «Подключить кнопки бота»
   или `php artisan app:tg-set-webhook`.
   - Сайт должен открываться по HTTPS, и в `APP_URL` должен быть указан этот адрес.
   - После смены токена бота кнопки нужно подключить заново.
2. **Проверить часовой пояс.** Расписание считается по `APP_TIMEZONE`, по умолчанию это UTC.
   Для московского времени: `APP_TIMEZONE=Europe/Moscow`.
3. Cron с `php artisan schedule:run` уже должен работать: на нём держится утреннее уведомление.

## Как проверялось

- Все новые и изменённые страницы на демо-данных в Docker отдают 200: главная, заказы с фильтром по дате,
  календарь (месяц, неделя, другой месяц, неверная дата), карточка клиента, настройки.
- Смена статуса: успешный запрос возвращает JSON, неверный статус — ошибку 422, без JS форма уходит с редиректом.
- Telegram проверен с подменённым API: тексты всех четырёх сообщений, клавиатура, регистрация webhook.
  Webhook: неверный секрет → 403, чужой чат → «Нет доступа», недопустимый статус → отказ,
  ACCEPT → PROGRESS → COMPLETE, откат COMPLETE → PROGRESS не происходит.
- **Не проверено:** внешний вид страниц в браузере и работа с настоящим Telegram.

## Ограничения

- Плашки карточки клиента пересчитываются только после перезагрузки страницы.
  После асинхронной смены статуса на «Отменён» суммы останутся прежними до перезагрузки.
- Утреннее сообщение отправляется одним сообщением. Если заказов очень много, оно может превысить лимит Telegram в 4096 символов.
  Так было и раньше.
