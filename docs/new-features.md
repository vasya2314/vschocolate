# Новые возможности: календарь, карточка клиента, быстрая смена статуса, аналитика на главной

Ветка: `feature/calendar-client-card-tg-reports`

## 1. Календарь заказов

**Где:** пункт «Календарь» в меню, кнопка «Календарь» в списке заказов, адрес `/orders/calendar`.

- Два режима: **Месяц** и **Неделя** (`?view=month|week`), стрелки «назад/вперёд», кнопка «Сегодня».
  Конкретный период открывается через `?date=Y-m-d`.
- Каждый заказ в ячейке дня: точка цвета статуса, время выдачи, **№ заказа** и товары.
  При наведении видны клиент, сумма и статус. Клик открывает страницу заказа.
- В режиме «Неделя» под заказом ещё клиент, сумма и долг, если заказ оплачен не полностью.
- Отменённые заказы зачёркнуты и не входят в сумму дня.
- Клик по числу дня открывает список заказов за этот день.
- На экранах уже 1024px (телефон, планшет, узкое окно) вместо сетки показывается вертикальный список по дням
  (только дни с заказами и сегодня).

Файлы: `OrderController::calendar`, `resources/views/pages/orders/calendar.blade.php`.

## 2. Переход от графика на главной к заказам дня

- Клик по столбцу графика «Заказы по дням» открывает список заказов за этот день.
- На телефоне первый тап показывает подсказку, второй открывает заказы.
- В фильтр заказов добавлены поля **«Дата выдачи с / по»** (`date_from`, `date_to`), ими можно пользоваться и вручную.

Файлы: `OrdersChartBlockComposers`, `components/blocks/orders-chart.blade.php`, `OrderFilter`, `Order/IndexRequest`.

## 3. Смена статуса без перезагрузки страницы

- В списке заказов и в карточке клиента бейдж статуса стал выпадающим списком.
- Новый статус сохраняется асинхронно, без перезагрузки: `PATCH /orders/{order}/status` через axios, ответ в JSON.
  Обратная связь показывается только на самом бейдже, без дополнительных значков:
  во время сохранения он полупрозрачный, после успеха ненадолго появляется зелёная обводка.
  При ошибке появляется красная обводка, значение откатывается, а текст ошибки виден во всплывающей подсказке.
- Ширина бейджа одинаковая для всех статусов, поэтому столбцы таблицы не сдвигаются.
- Без JavaScript форма отправляется обычным способом с редиректом назад.
- Имя клиента в списке заказов стало ссылкой на его карточку.

Файлы: `components/orders/status.blade.php`, `OrderController::updateStatus`, `Order/UpdateStatusRequest`.

## 4. Карточка клиента

**Где:** страница клиента `/clients/{id}`, раньше на её месте была только форма редактирования.

- Шапка: имя, телефон (по нажатию звонит), площадка, дата первого и последнего заказа.
- Плашки: **число заказов** (и сколько отменено), **общая сумма**, **средний чек**, **долг**.
  Отменённые заказы в суммы не входят.
- Ниже прежняя форма редактирования клиента.
- В самом низу **история заказов** по 20 на странице, с быстрой сменой статуса.

## 5. Аналитика на главной

Все показатели считаются по уже существующим данным, новые столбцы в БД не понадобились.
Месяц выбирается в фильтре «Месяц», период — по дате выдачи заказа.

| Блок | Что показывает | Период |
|---|---|---|
| Плашки | Новые клиенты, выдано на сумму, заказов к выдаче, **средний чек**, в ожидании, **доля отмен**; у всех, кроме «в ожидании», — **изменение к прошлому месяцу** (▲/▼ %; для доли отмен — «▼ было 7,8% в прошлом месяце», рост отмен — красный) | выбранный месяц |
| Выручка по месяцам | Сумма неотменённых заказов по месяцам года; клик по столбцу открывает этот месяц | год выбранного месяца |
| Источники клиентов | По площадке клиента: новые клиенты, заказы, выручка и её доля | выбранный месяц |
| Популярные товары | Топ-10: в скольких заказах встречается товар и в какой доле заказов | выбранный месяц |
| Повторные клиенты | Доля заказов месяца от клиентов с 2+ заказами за всё время; топ-10 клиентов по сумме за всё время | месяц / всё время |
| Нагрузка по дням недели | Среднее число заказов на один такой день (Пн…Вс) | 12 месяцев до конца выбранного (или с первого заказа) |
| Долг клиентов | Недоплата по выданным заказам (итог и список должников), ожидаемая доплата по невыданным | всё время |

- Средний чек = сумма неотменённых заказов / их количество.
- Прошлый месяц сравнивается целиком, поэтому в середине текущего месяца «выдано на сумму» обычно ниже прошлого.
- Выручку по товарам посчитать нельзя: количество и цена товара в заказе не хранятся.

Файлы: `app/View/Composers/Blocks/*BlockComposers.php`, `resources/views/components/blocks/*.blade.php`,
`pages/dashboard.blade.php`, `kopToRubShort()` в `app/_export.php`.

## Исправления

- **«Заказов к выдаче» на главной** больше не учитывает отменённые заказы.
- **Суммы заказов хранятся в целых копейках** (`BIGINT` вместо `DOUBLE`), миграция
  `2026_11_26_000000_change_order_amounts_to_integer`. Существующие значения при миграции округляются до целых копеек.
  - Сумма из формы («12 345») переводится в целое число рублей до вызова `rubToKop()`, а `rubToKop(int): int` принимает только `int`
    (`app/Http/Requests/Order/Concerns/PreparesAmounts.php`). Дробные и нечисловые значения отклоняются валидацией
    (`integer|min:0`), а не ошибкой 500.
  - В модели `Order` суммы приводятся к `int`.

## Как проверялось

- Все новые и изменённые страницы на демо-данных в Docker отдают 200: главная, заказы с фильтром по дате,
  календарь (месяц, неделя, другой месяц, неверная дата), карточка клиента, настройки.
- Смена статуса: успешный запрос возвращает JSON, неверный статус — ошибку 422, без JS форма уходит с редиректом.
- Вёрстка календаря, карточки клиента и главной проверена в Chrome на ширине 390px (телефон), 776px и десктопе.
- Главная открывается за текущий, прошлый и пустой месяц (2020-01).

## Ограничения

- Плашки карточки клиента пересчитываются только после перезагрузки страницы.
  После асинхронной смены статуса на «Отменён» суммы останутся прежними до перезагрузки.
